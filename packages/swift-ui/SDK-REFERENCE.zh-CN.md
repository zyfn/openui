# OpenUI Swift SDK 设计与组件说明

本文说明 **当前 main 的 SDK 设计**：为什么这样组织界面、每个组件怎样处理，以及流式生成带来的限制。面向产品、Agent、客户端和服务端开发者。

视觉基准：[`0.1.1-rc.18`](https://github.com/zyfn/openui/releases/tag/0.1.1-rc.18)，提交 `fa23218f`。当前 main 的标准 SDK 有 **87 个组件**，包括已迁入的 Map、MapPoint、SVG；生成库是否排除 ImageBlock，由客户端决定。Map/SVG 迁入尚不代表已发布新的 RC。

## 1. 先看这七条

1. **模型决定内容和结构，SDK 决定具体呈现。** 模型使用固定 DSL，不需要知道某个角色是几 pt；不通过业务词或 case 名称触发特殊样式。
2. **同一文字职责使用同一份主题映射。** 字体、字号、字重、颜色和行距一起解析，普通文字与加载占位使用对应的同一角色。
3. **父容器分配空间，子内容在空间内增长。** 长文字在列内换行，图片按分配宽度和媒体比例布局；不靠后到的文字持续撑宽图片。
4. **Card 组织可分配空间的内容单元，表面由 variant 决定；Form 表达填写与提交边界。** clear Card 无边框、无内边距，仍参与横排宽度分配；Form 默认复用 Card 的外观。
5. **流式更新保留已显示内容。** 未完成的结构、数字、引用、图片和请求分别处理，不用整段隐藏或重建来等待完成。
6. **交互产生事件，宿主负责真正执行。** SDK 提供表单值、动作及上下文；是否发给 Agent、打开页面或调用业务系统，由宿主完成。
7. **示例教组织方法，不充当实时查询结果。** 标题、图片、介绍、规格、价格和入口必须对应；计划、预算和查询事实有明确区别。

## 2. 系统怎样连接

```text
模型输出 OpenUI Lang 分片
  → 共享语言核心解析和求值
  → OpenUIState 保持状态、引用、查询及动作
  → 原生渲染器按组件契约与就绪状态呈现
  → 用户交互更新状态或产生 ActionEvent
  → 客户端宿主处理导航、业务执行和 Agent 请求
```

| 部分 | 负责什么 | 不应越界做什么 |
| --- | --- | --- |
| Lang 和注册库 | 组件名称、参数、数据、引用、绑定、函数与动作 | 不为某个页面添加专属语法 |
| SDK | 原生布局、主题、媒体、控件、流式呈现、事件生成 | 不编商品事实，不自动执行交易，不推测 Agent 的业务进度 |
| 客户端宿主 | 注册实际扩展、提供资源、消费事件、生成实际 Lang | 不只转交消息而丢失表单值，不用额外样式补洞 |
| 服务端／Agent | 使用客户端导出的规范、取得真实数据、生成合理组合 | 不手写另一份组件契约，不把案例中的价格当本次查询结果 |

**最终规范来自客户端实际注册库。** SDK 基础库与客户端注册库可能不同。客户端通过标准 `PromptOptions.examples` 加入用例，再导出 prompt、spec、schema 和追溯 manifest，服务端消费这一份产物。

## 3. 统一视觉规则

### 3.1 文字和颜色

系统字体为默认字体，代码使用等宽字体，数字按需要使用等宽数字。保留系统语言字形和 Dynamic Type 能力。

| 职责 | 默认尺度 | 字重／颜色 | 主要位置 |
| --- | --- | --- | --- |
| 总标题 | 26pt | Semibold，主色 | 完整方案的总标题；普通短回复不必强加 |
| 章节标题 | 20pt | Semibold，主色 | Day、交通、方案比较等主要章节 |
| 对象标题 | 18pt | 标题字重，主色 | CardHeader、InlineHeader、图文对象名称 |
| 连续正文 | 16pt | Regular，主色 | 原理、行程和主要回答 |
| 紧凑正文 | 14pt | Regular，主色 | 卡片内短介绍、简短理由 |
| 辅助信息 | 14pt | Regular，辅助色 | subtitle、subtext、提示和补充信息 |
| 图注角色 | 13pt | Regular，辅助色 | 来源、位置计数等明确的图注槽位 |
| 数字值 | 14／16／18pt | 数字角色，按强调设置字重 | 时间、金额、指标 |
| 操作文字 | 14／16pt | Medium | 小型／常规按钮 |

| 颜色职责 | 浅色模式 | 深色模式 |
| --- | --- | --- |
| 主文字 | `#303036` | `#E4E4E7` |
| 辅助文字 | `#64646E` | `#A1A1AA` |
| 链接 | `#202024` | `#F4F4F5` |

高对比模式保留更强的黑白对比。状态色只表达明确状态；图片上的文字使用媒体覆盖层的对比策略。

**字号小不等于信息次要。** `TextContent(small)` 是紧凑主文字；subtitle、subtext 等明确辅助槽位使用辅助色。标题与正文可以同色，通过字重、字号和间距区分。影响决定的条件不能仅因文字小就被淡化。


文字映射集中在 [Theme/TextStyles.swift](Sources/OpenUISwiftUI/Theme/TextStyles.swift)，具体值在 [OpenUITheme.swift](Sources/OpenUISwiftUI/Theme/OpenUITheme.swift)。默认行高倍率：正文 1.50、详情 1.45、图注 1.40、对象标题／字段标签 1.35、章节 1.30、展示标题／操作／指标 1.25。原生字形高度是下限；宿主显式设置的完整字体与行距优先。

### 3.2 容器、按钮与边界

| 对象 | 当前规则 |
| --- | --- |
| Stack | 管排列、对齐、间距与换行；不自动把任意子项变成等宽列 |
| Card | 直接放在横排中可共享宽度；wrap 开启时按现有阅读宽度换行，文字增长不改变该宽度依据；额外包普通 Stack 会改变父级看到的布局项 |
| Card(card) | 有边框、背景及内边距，表达完整对象 |
| Card(sunk) | 有浅底和内边距，无分组边框 |
| Card(clear) | 保留空间分配能力，两轴内边距为零；列间距只由父容器管理 |
| Form | 默认与 Card 共用边框、圆角和内边距；字段与提交按钮属于一个任务面板 |
| 分隔线 | 用于记录边界或结构关系；有章节标题和留白时，不再机械叠加横线 |
| Tag | 表达短属性、条件或状态；普通属性使用中性色，完整解释留在正文 |

所有原生卡片网格都按可用宽度、间距和现有最小列宽计算，不再混用 480／768 固定断点。完整对象、图片型卡片和左右摘要使用对象阅读宽度；Overview 的紧凑内容使用紧凑阅读宽度，横向图文头保留对象阅读空间。各家族最大列数与显式 responsive=false 的布局选择保留。

clear 的零内边距和 Form 的默认卡片外观，是明确的 Swift 呈现策略，与固定 React 参考外观不同；**没有新增 Lang 参数**。宿主已有面板时，可显式设置 `formShowsCardSurface=false`。SDK 不按业务内容猜测是否加框。

按钮的 **重要性、尺寸、宽度是三个独立维度**：variant 表达重要性，size 选择尺寸，布局决定是否铺满。

| 文字按钮档位 | 字号 | 左右内边距，每侧 | 上下内边距，每侧 | iOS 可见最小高度 |
| --- | --- | --- | --- | --- |
| extra-small | 14pt | 8pt | 4pt | 28pt |
| small | 14pt | 12pt | 6pt | 32pt |
| medium | 16pt | 16pt | 8pt | 40pt |
| large | 16pt | 18pt | 10pt | 48pt |

表中为正常字号的普通文字 primary／secondary 按钮。长文字和系统字号可增加高度；tertiary、纯图标按钮有各自内边距。iOS 外层触控区域至少 44pt，**不会据此把小胶囊底色画成 44pt**。同行可对齐外层触控区域，短按钮底色仍保持自己的尺寸；纵排可铺满宽度。大按钮用于独立主要动作，不是卡内入口的常用默认。

## 4. 最难的部分是流式过程中保持可信与连续

| 难点 | 容易出现的问题 | RC18 的处理 |
| --- | --- | --- |
| 结构参数尚未到达 | 先猜成一种布局，收到 wrap／方向后突然重排 | 按组件声明布局依赖；未确定布局时只显示安全的阅读前缀。横排所有宽度贡献项已知后显示媒体；Card 的阅读宽度不依赖尚未结束的文字 |
| 前向引用还没解析 | 为了等后面的组件，把前面文字清空 | 保留源顺序和原槽位；使用同一布局子树与稳定身份，不切换另一套临时视图 |
| 数字只到了一半 | 把 `1` 当最终值，随后变成 `100`；缺值补成零 | 区分临时与已完成值；图表只消费可确认数据，不补造零 |
| 内容继续增长 | 图片随文字变宽，选择项因为字多反复换列 | 父级分配宽度；选择卡按可用宽度和最小列宽排布，文字在列内向下增长 |
| 集合逐项到达 | 第一张卡先占满，后续到达后突然缩小 | 卡片组／图库可用已知集合形状确定几何；未知条目不变成假控件或可滑动目标 |
| 图片下载与源码不同步 | 整张卡等图片，或者用黑块充当图片 | 结构、文字、完整 URL、下载完成分别处理；中性占位保留媒体角色，不阻挡整组内容 |
| 查询刷新或中断 | 已有图表、图片被清空；未完成值被当成结果 | 保留已提交内容和稳定数据；中断不等于提交临时值，宿主仍负责取消传输 |
| 图表等待数据 | 出现大面积假网格、假圆环，完成后整块替换 | 首次等待使用局部延迟反馈；有意义的数据逐步显示；依赖完整总量的比例图等待必要数据 |
| 可点击范围与视觉尺寸混用 | 相同 small 放进 Buttons 后突然变大 | 行高作用于外层触控区，标签和绘制表面按自然内容及尺寸档位布局 |
| 跨平台语言语义 | Swift 自行解释字符串、表达式或正则，导致相同程序行为不同 | 共享语言核心保持语义；原始字段名和状态使用精确字符串表示，显示转换不回写数据 |
| 请求晚于消息切换返回 | 旧 Query／资源覆盖新消息，定时刷新仍继续 | 以来源版本和资源作用域隔离回调；替换、重置和释放使旧请求失效；实际工具传输由宿主提供 |
| 交互值传不到 Agent | 点击有文案，Agent 却不知道选了什么 | 事件保留 formName／formState；客户端通过现有 SDK 消息封装将当前值一起交给 Agent |

加载反馈采用局部、延迟出现的原生动画，避免短等待闪一下。SDK 不生成“正在整理内容”等业务叙述。不同组件有不同的就绪规则，不能把所有组件统一成“完整后才显示”或“任何残片都立即显示”。

**容器不是灰色骨架。** 它先确定关系和空间；未知数据不应被画成虚构的完整页面。

重复的最终快照和空分片是幂等输入，不应重置已挂载内容、图片缓存或用户字段；明确重播仍使用 `reset()`。客户端如果主动更换 State、消息身份或重置程序，SDK 不能替宿主保留旧视图。


图片预览与原来卡片内的缩略图／16:9 裁切互相独立：原位置保持既定布局，预览完整原图并支持缩放。普通图片点击预览；动作卡、选择卡中的图片通过长按菜单预览，避免抢走原有操作。网络失败后点击原图位置重试，显示局部加载动效，不另添 Retry 按钮。

单页和网格不参与翻页手势；iOS 18 起，横滑在识别开始前排除纵向意图，交给外层阅读滚动。旧系统保留兼容手势路径。

## 5. 逐组件处理

下列 84 项来自 RC18 标准注册库。表中的 Item／数据组件由父组件消费，单独渲染为空并非缺失实现；不能为它们随意套 Stack 改变类型关系。

### 5.1 布局与内容边界

| 组件 | 用途 | 当前处理与边界 |
| --- | --- | --- |
| Stack | 连续阅读、行列分组 | 管 direction、gap、align、justify、wrap；保留普通内容宽度，不隐式等宽；等待布局参数时保留安全前缀 |
| Card | 完整对象或独立内容单元 | 共享横排空间；card／sunk／clear 各自边界规则固定；不裁掉内容边缘字形，不用它包装所有章节 |
| Separator | 结构分隔 | 复用边界色；横线不作为每个标题的装饰；交通连接线与章节分隔按用途区分 |
| Carousel | 按页浏览多组内容 | 外层数组是一组页面，内层数组是单页内容；不把页面数组拍平；遵守合法 children 类型，不能塞任意 Card／Stack |

### 5.2 文字、提示与图标

| 组件 | 用途 | 当前处理与边界 |
| --- | --- | --- |
| TextContent | 普通讲述 | 支持 Markdown；大小和加重选项映射既有文字角色；可直接写文字，不强制每句话拆变量 |
| MarkDownRenderer | 带章节的正文 | 标题层级走主题映射；链接下划线；card／sunk 外观按参数；不重复包章节 Card |
| CardHeader | 对象名称与副标题 | 标题走对象角色，subtitle 走辅助角色；两字段均可选，只有 subtitle 也能正常显示 |
| InlineHeader | 行程节点、小组标题 | 与对象标题共用标题映射，description 使用辅助样式；不为名称另造字号 |
| Text | 短文字或数字 | 按 size／variant 解析；value 与 subtext 分工；普通数字不随正文统一放大 |
| BoldText | 重要文字或数值 | 复用 Text 路径并强调字重；subtext 仍是辅助角色；不靠把整段正文加粗制造重点 |
| Label | 字段或短说明标签 | 使用既有正文尺度；它本身不建立输入绑定或校验关系 |
| Icon | 图形识别 | 使用固定 Lucide 目录及分类映射；图形名称不自动决定成功／警告等业务颜色 |
| IconText | 图标与文字 | 图标与整组标题／说明垂直居中；默认 m 为 20pt，l 为 24pt、xl 为 28pt，xs／s 保持紧凑；普通样式中性、无彩色圆底，显式状态保留语义色 |
| Callout | 说明或可反馈状态 | 普通说明采用轻量竖线；成功／警告／错误保留小状态图标和语义；reactive visible 支持自动消退 |
| TextCallout | 静态提示 | 复用提示视觉，但不假装执行 Callout 的响应式消退；说明与真正状态区分 |
| Tag | 一个短属性／状态 | 普通属性中性胶囊；状态色需有依据；照片上使用稳定对比覆盖层，缺图时保持可读 |
| TagBlock | 多个短属性 | 自动横向排列与换行；不重复标题和价格已有信息；不将完整前提或长段解释塞进标签 |
| CodeBlock | 代码阅读和复制 | 等宽字体、语言标识、横向阅读长行、原生复制反馈；代码不当作 Agent 已执行结果 |

### 5.3 图片与图文对象

| 组件 | 用途 | 当前处理与边界 |
| --- | --- | --- |
| Image | 单图 | 媒体比例依据角色；父级分配宽度，中性缺图占位；点击预览，失败后点击原位重新加载，恢复局部动画，不显示 Retry 按钮 |
| ImageBlock | 独立图片块 | 按媒体比例与圆角显示一张图片，支持预览及原位点击重试；SDK 渲染库支持；当前客户端生成库明确排除，模型应以客户端实际 spec 为准 |
| ImageGallery | 一组相关图片 | 根据实际可用宽度、间距和现有紧凑阅读宽度分列，不在窄容器硬塞三列；已知集合形状先分配宽度，内联预览最多按五个可见槽分列，下载只替换画面；支持原图预览与缩放、原位重试和刷新保留内容 |
| ImageText | 缩略图＋名称／说明 | 横排图片与整组文字居中；无指定尺寸时按可用阅读空间调整缩略图，显式 imageSize 保持原意 |
| ImageTextLarge | 大图对象头 | 默认 16:9 媒体框与覆盖裁切；名称与说明走统一角色，卡内可与外层边界协调出图。不会因来源图片是方图或海报而改成完整适配 |

### 5.4 列表、指标与表格

| 组件 | 用途 | 当前处理与边界 |
| --- | --- | --- |
| EntityList | 名称—值、条件—结果 | 稳定左右等宽列，各自换行；名称辅助色、文字值中等强调、数值右对齐；记录间轻线，末行无线；不因长值整行改排 |
| ListBlock | 多条列表内容 | 父级组织 ListItem，密度和文字层级共享；不额外制造每项一张大卡 |
| ListItem | 单条列表内容 | 展示标题、说明及合法操作；操作与对应条目绑定，不扩大为整页点击 |
| MetricIndicatorInline | 行内指标与比较 | 能并排时按基线组织，空间不足可将说明下排；数值本体保持完整 |
| MetricIndicatorWithStrikethrough | 当前值、旧值与趋势 | 当前值突出，旧值删除线，趋势与说明次级；不把涨跌天然解释成业务好坏 |
| Table | 多对象字段核对 | 管列宽、表头、单元格及横向视口；宽表允许横向阅读，不靠缩小所有文字强塞 |
| Col | 表格列定义 | 定义列名称、数据及类型，由 Table 消费；不独立显示、不额外包容器 |
| EditableTable | 表格内编辑 | 原生编辑和状态写回；表格边界消费外部 stretch，避免泄漏到单元格按钮 |

EntityList 是固定两列记录，指标说明可以上下重排，Table 自己管理列网格；三者不是同一种布局策略。超宽 Metric 数值通过横向阅读保持完整，不拆小数或强行缩字。

### 5.5 表单与选择控件

| 组件 | 用途 | 当前处理与边界 |
| --- | --- | --- |
| Form | 收集信息后统一提交 | 默认 Card 任务面板；维护精确表单作用域、校验及字段值；宿主可显式取消表面；不把纯展示或单个跳转包装成 Form |
| FormControl | 单个字段单元 | 将 label、input、hint 关联；复合控件可通过渲染注册信息承接标题，避免再插一行标签；普通输入保留外部标题；错误与字段就近显示 |
| Input | 单行输入 | 原生文本输入、相应类型与校验；按字段状态绑定，避免源码更新覆盖用户输入 |
| TextArea | 多行输入 | 保留多行编辑、选择和光标；内容可自然增长，字段身份不随重排重建 |
| Select | 下拉选择 | 菜单／原生选择呈现；值由对应 SelectItem 提供；显示值与实际 value 对应 |
| SelectItem | 下拉选项记录 | 由 Select 消费标签、值、禁用状态；不独立创建第二个控件 |
| DatePicker | 日期或范围 | 原生日期呈现，遵循已注册契约和最近 locale；不把未到达日期补成一个业务结果 |
| Slider | 数值范围调整 | 标题与当前值同排，下方轨道及辅助说明；不重复叠放数值灰框。连续值保留精确编辑，离散值保留选择器；iOS 不铺满刻度圆点，取值和步长语义不变 |
| CheckBoxGroup | 多选或本地勾选 | 单值变化写入共享字段状态；是否统一提交由外部任务决定，不必总有 Form |
| CheckBoxItem | 多选项记录 | 由 Group 读取 value、标签、描述及禁用状态 |
| RadioGroup | 单选 | 统一选择存储和禁用行为；控制是否可提交由表单校验处理 |
| RadioItem | 单选项记录 | 由 RadioGroup 消费，不自行维护另一份选择 |
| SwitchGroup | 多个开关值 | 使用原生开关表达开启／关闭，状态写回同一字段体系 |
| SwitchItem | 开关记录 | 提供值、标签及说明，由 Group 维护状态 |
| Chips | 紧凑选择 | 支持契约内的单选／多选，自动换行；它是可操作控件，与静态 Tag 区分 |
| ChipItem | 紧凑选项记录 | 提供键、标签、图标及禁用信息，由 Chips 消费 |
| OptionCards | 带图／说明的选择 | 列数由可用宽度与既有最小列宽确定；长文案只增加行高；更窄空间和辅助功能大字号可单列 |
| OptionCard | 选择卡记录 | 真实控件只挂载一份；呈现图片／图标、标题、说明和选中状态，按 value 更新选择 |

**Form 的判定条件是需要收集用户值并明确提交，不是“出现了按钮”。** 一个字段也可以形成 Form；即时筛选、无需提交的清单、纯内容和直接跳转不必使用 Form。

必填校验阻止空提交，中文必填反馈由原生本地化资源提供；语言核心的错误值不被改写，未知自定义提示保持原文。当前主要表单提交按钮触发现有提交校验；普通导航动作不应被当作提交。

### 5.6 操作与后续请求

| 组件 | 用途 | 当前处理与边界 |
| --- | --- | --- |
| Button | 一个明确动作 | 根据 label 和已确认外观显示；pending、performing、disabled 分开；小按钮不被同行的触控高度撑大 |
| Buttons | 一组动作 | row 自然宽度并逐项换行；column 铺满宽度；保持同一批控件身份，外层目标可同行对齐 |
| IconButton | 图标动作 | 明确可访问名称、原生目标范围；方形／圆形遵循参数，不用图标猜测业务行为 |
| FollowUpBlock | 一组继续提问 | 作为回复末尾的后续入口组织；保持可读与可点击范围，不当作正文标签 |
| FollowUpItem | 一条后续提问 | 点击产生继续对话事件；宿主决定如何进入实际 Agent 链路 |

“购买”“预订”“查看票价”“查询车次”应对应真实目标页面或行为。官方价格公示链接不能被包装成已查库存的预订操作。

### 5.7 卡片家族

Item 定义单个对象，Block 定义一组对象及其 grid／carousel 等排列。当前卡片组契约要求至少两项；单对象使用合法的单对象组合，不虚构第二个候选。

| 组件 | 用途 | 当前处理与边界 |
| --- | --- | --- |
| SnippetCardItem | 紧凑对象摘要 | 名称、图标或缩略图、简短说明形成摘要；lhs／rhs 的文字值保持左右关系，长地址在右列内部换行；数字／指标保留完整数值所需宽度，空间不足时允许下排；内容与操作属于同一对象 |
| SnippetCardBlock | 摘要集合 | 仅支持 grid；responsive 默认启用，以对象最小阅读宽度分列、最多两列；复用集合几何与逐项就绪策略 |
| OverviewCardItem | 对象概览和关键值 | 主要信息与底部指标分层；同一网格行的指标起点对齐，说明长短不把数值挤到不同高度 |
| OverviewCardBlock | 概览集合 | 组织可比较条目；维持行内对齐与可用宽度，不依赖选中页决定集合高度 |
| ContextCardItem | 背景或情境说明 | 可有背景图；文字与图片覆盖层保持对比，缺图时转为中性可读内容 |
| ContextCardBlock | 情境集合 | 按布局参数呈现；不将整组图片下载完成作为文字展示门槛 |
| CompositeCardItem | 商品、酒店、票务等完整对象 | 大图铺满卡片顶部并沿用卡片上方圆角；标题、body、footer 保留面板留白，body 放短介绍／属性；footer 与通用 row／between／wrap 共用布局，空间不足时价格与操作下排，保留同一操作实例 |
| CompositeCardBlock | 完整对象集合 | 支持网格／横滑；已知集合数稳定先到条目的宽度，单卡可先于整组出现 |
| VisualCardItem | 图片主导的视觉入口 | 标题、短描述和 Tag 叠图；渐变与深色半透明胶囊保证可读；缺图不变成黑色大块 |
| VisualCardBlock | 视觉入口集合 | 图形结构与下载分开；照片可预览，已有整卡动作时通过长按菜单预览，单击仍执行卡片动作；横滑只处理水平意图 |

商品对象的信息职责为：**对象名称与身份 → 简短介绍 → 必要属性／规格 → 价格口径与动作**。这是商品内容组织原则，不是所有卡片的固定视觉顺序；Visual、Snippet、Overview 等仍遵循各自槽位。主要事实和推荐理由分清；短属性可用中性 Tag，长前提留正文。核心对象可以展开，补充推荐使用更紧凑的头部或支持 carousel 的集合。

### 5.8 导航、步骤与面板

| 组件 | 用途 | 当前处理与边界 |
| --- | --- | --- |
| Tabs | 同一区域切换内容 | 用户未操作时可跟随最后增长的面板；用户选择后尊重选择；宽标签横向阅读并提示溢出 |
| TabItem | 页签记录 | value 是稳定身份，trigger 是标签，content 是内容；不按显示文案重新识别 |
| Accordion | 辅助内容折叠 | 原生折叠，当前实现维护一个展开项；分隔记录边界，长标签可换行 |
| AccordionItem | 折叠项记录 | 提供稳定 value、标题和内容，由 Accordion 呈现 |
| Steps | 有顺序的步骤 | 序号、标题、详情和连线形成顺序；标记随文字尺度增长，不裁切数字 |
| StepsItem | 步骤记录 | 由 Steps 消费；不能用它假装已经执行了业务步骤 |
| Modal | 独立临时面板 | 原生 sheet，open 可绑定共享状态，关闭写回当前呈现；内容与尺寸按面板空间组织 |

### 5.9 图表与数据组件

图表共享数据解析、图例、坐标测量和检查交互；具体图形仍遵守各自语义。默认使用平台系统蓝、橙、绿、紫、粉、青、靛等语义颜色，适配深浅外观，不再使用矿物／陶土定制色或按类别强制铺蓝色深浅。颜色按原始系列／占比分类对应，流式追加、排序和图例筛选不改变已有颜色。坐标标签采用统一图注角色，网格减轻，图例采用紧凑圆点；不以装饰替代数据关系。

| 组件 | 用途 | 当前处理与边界 |
| --- | --- | --- |
| BarChart | 分类数量比较 | 分类完整后，已确认数值形成柱；缺数据不补零，轴与图例为数据留阅读空间 |
| HorizontalBarChart | 长分类名称的数量比较 | 使用横向柱形和对应分类轴；遵守相同数据与图例规则 |
| LineChart | 趋势 | 分类完整后，完整数据点逐步形成线；不把未完成的尾数字当成真实点 |
| AreaChart | 趋势与覆盖面积 | 复用笛卡尔数据／坐标规则，面积只代表已确认的数据 |
| RadarChart | 多维轮廓 | 分类与系列完整后呈现；分类标签有独立测量空间；类别轴与数值含义对应，不用缩字掩盖密集标签 |
| PieChart | 部分与整体 | 依赖可确认的完整总量再表达占比，避免把暂时总量当最终比例 |
| RadialChart | 环形比例 | 同样等待比例所需数据；首次等待不画假圆环充当结果 |
| SingleStackedBarChart | 单条组成关系 | 使用较低的原生图形高度；图例可换行，数值与整体条件一致 |
| ScatterChart | 二维点分布 | 成对、可确认的坐标组成点；按散点投影与邻近点检查，不混用分类索引 |
| Series | 笛卡尔／雷达系列数据 | 由图表消费名称、值和对应信息；不单独显示 |
| Slice | 目录中的数据定义 | 不独立渲染；当前 PieChart 接口仍接收 labels／values 数组，不能因有 Slice 定义就替换输入类型 |
| ScatterSeries | 散点系列 | 提供一组 Point，由 ScatterChart 解释 |
| Point | 单个散点数据 | 保留 x／y 成对含义；不独立生成图形视图 |

初始等待、刷新已有结果、流被中断、实际数据失败是不同状态。刷新时可以保留已有图；按图形语义逐步显示真实数据，不等于每个图都必须逐点动画，也不等于整个图一直等到全文结束。

## 6. 地图与图解进入 SDK

| 组件 | 负责什么 | 边界 |
| --- | --- | --- |
| Map | 地点位置、标记和关联对象浏览 | SDK 使用 MapKit，支持标记、地点卡联动与全屏；仅选中地点显示地图标题，避免邻近地名叠在一起；地图要求 iOS 17／macOS 14，旧系统明确提示；地点图不等于已取得导航路线或实时交通 |
| MapPoint | 地点记录 | 提供名称、坐标、图片及说明，由 Map 消费；坐标系必须匹配 |
| SVG | 原理图、结构图 | SDK 在隔离 WKWebView 中渲染；inline content 与 HTTPS src 二选一，必须有正数 viewBox；禁用脚本、外部引用与交互导航，内容上限 1MB |

Map、MapPoint、SVG 现在由 SDK 默认注册，保留原宿主参数顺序。Card、TabItem、AccordionItem 的既有内容槽通过共享核心扩展接受 Map／SVG；无需新增 Lang 语法。宿主应删除同名自有实现，再从实际库导出规范。

MapPoint 的标题与坐标确认后才能成为标记；可选说明继续到达不改变地点身份。SVG 使用树级资源 loader，不绕开宿主资源策略。最终规范仍应由客户端实际注册库导出。

### Form 消息怎样传给 Agent

标准路径是：`ActionEvent → buildMessage(content, context) → 现有用户消息字符串 → Agent`。context 可以携带点击说明、formState 和动作 context；客户端用 `parseMessage` 分离显示文字与上下文，避免把结构信息直接显示成聊天正文。

Swift SDK 已公开这两个 API，固定 React Chat 参考实现也使用这条路径。既有 `query: String` 可以承载封装后的字符串；此前“必须新增服务端表单字段”的判断不成立。当前缺口是客户端尚未完整使用该封装，不是 SDK 没有表单值，也不是静态 Lang 缺少字段。是否真正到达并被模型使用，需要接通后的实际联调证明。
